# Tic-Tac-Toe API

Сделал REST-сервис крестиков-ноликов на Spring Boot: регистрация, JWT, партия с компьютером или со вторым игроком, история партий и таблица лидеров. На том же приложении отдаётся одностраничный клиент.

## Стек

- Java 18, Spring Boot 4, Gradle
- Spring Web, Spring Security, Spring Data JPA
- PostgreSQL
- JWT (jjwt), пароли в BCrypt

## Что умеет

- Регистрация и вход. Access-токен живёт 15 минут, refresh — 30 дней. Сессий на сервере нет.
- Игра 3×3 против компьютера. Ход компьютера считает minimax, поэтому он не проигрывает.
- Игра против человека: создатель ждёт второго игрока, тот присоединяется к открытой партии.
- Ход принимается только от того, чей сейчас ход, и только как одна новая фишка в пустую клетку.
- История побед и ничьих текущего пользователя.
- Таблица лидеров по соотношению побед к поражениям и ничьим.

Разделил код на слои: `web` (контроллеры и DTO), `domain` (правила и minimax), `datasource` (JPA и PostgreSQL).

## Запуск

Нужны JDK 18+ и PostgreSQL. База и пользователь из `application.properties` — локальные, для демо:

```sql
CREATE USER xo WITH PASSWORD 'xo';
CREATE DATABASE xo_t05 OWNER xo;
```

```bash
./gradlew bootRun
```

На Windows: `gradlew.bat bootRun`.

Приложение: [http://localhost:8080](http://localhost:8080). Схема таблиц создаётся при старте (`ddl-auto=update`).

Секреты JWT можно переопределить переменными `JWT_ACCESS_SECRET` и `JWT_REFRESH_SECRET`. Строка секрета должна быть не короче 32 байт.

## API

Кроме `/auth/**` и статической страницы все запросы требуют заголовок `Authorization: Bearer <accessToken>`.

### Авторизация

| Метод | Путь | Тело | Ответ |
| --- | --- | --- | --- |
| POST | `/auth/register` | `{ "login", "password" }` | `true` или `false` |
| POST | `/auth/login` | `{ "login", "password" }` | `{ "type": "Bearer", "accessToken", "refreshToken" }` |
| POST | `/auth/token` | `{ "refreshToken" }` | новая пара, refresh тот же |
| POST | `/auth/refresh` | `{ "refreshToken" }` | новая пара токенов |

Неверный логин или токен — `401` без тела. Повторный логин при регистрации — `false`.

### Пользователь

| Метод | Путь | Ответ |
| --- | --- | --- |
| GET | `/user/me` | текущий пользователь: `id`, `login`, `roles` |
| GET | `/user/{uuid}` | тот же формат, `404` если нет |

### Игра

Поле — матрица 3×3: `0` пусто, `1` крестик, `2` нолик. Состояния: `WAITING`, `TURN`, `WIN`, `DRAW`.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/game` | Новая партия. Тело необязательно: `playerSymbol` (`1` или `2`), `opponent` (`COMPUTER` или `USER`). Без тела — крестики против компьютера. |
| GET | `/game/available` | Партии в `WAITING`, к которым текущий пользователь ещё не присоединился |
| POST | `/game/{uuid}/join` | Занять свободную сторону и начать партию |
| GET | `/game/{uuid}` | Текущее состояние |
| POST | `/game/{uuid}` | Ход: в теле полное поле `field` с одной новой клеткой |
| GET | `/game/history` | Победы и ничьи текущего пользователя, новые сверху |
| GET | `/game/leaderboard?n=10` | Топ игроков. Параметр `n` обязателен и больше нуля; вместо него можно передать `limit` |

Пример создания партии против компьютера за нолики:

```http
POST /game
Authorization: Bearer <accessToken>
Content-Type: application/json

{ "playerSymbol": 2, "opponent": "COMPUTER" }
```

Если игрок выбрал нолики, первый ход сразу делает компьютер.

Пример хода — всё поле после постановки крестика в центр:

```http
POST /game/{uuid}
Authorization: Bearer <accessToken>
Content-Type: application/json

{ "field": [[0,0,0],[0,1,0],[0,0,0]] }
```

Ошибки хода возвращаются текстом: `400` (партия закрыта, поле неверное, нет второго игрока), `403` (сейчас ход другого), `404` (партии нет).

### Рейтинг

`winRatio` — число побед, делённое на число поражений и ничьих. Если поражений и ничьих нет, в рейтинг попадает само число побед. В выборку входят только завершённые партии (`WIN` и `DRAW`). Сортировка: рейтинг по убыванию, затем логин.
